## 1. Видение продукта

**VisuSic** — десктопный (Windows, позже Android) редактор музыкальной визуализации, который закрывает две задачи одним инструментом:

1. **Лирик-видео**: загрузил трек → приложение само нашло синхронизированный текст в сети → накидал на поле виджеты → экспортировал MP4 в нужном соотношении сторон за пару минут. Без After Effects, без таймлайна на 200 слоёв, без подписки.
2. **Real-time визуализация**: играет музыка (файл, плейлист, позже — системный звук/микрофон) → на экране живая сцена, которая реагирует на ритм. Это и «красивый фон на втором мониторе», и режим для стрима, и превью того, что потом уйдёт в видео.

**Ключевая идея-отличие.** Аналоги (MilkDrop/ProjectM, Winamp AVS, Specterr, Vizzy, шаблоны в CapCut) — это либо список готовых неуправляемых пресетов, либо тяжёлые монтажки. У нас — **конструктор сцены**: виджеты кладутся на поле как в Figma, у каждого есть понятная панель параметров, а внешний вид описывается **открытым форматом шаблонов**. Любой может сделать свой виджет или целую сцену, положить в папку — и он появится в приложении. Никакой пересборки.

**Главная фича, на которую уходит половина усилий — «удобно добавить и настроить виджет».** Не «есть 40 эффектов», а «добавить эффект занимает 5 секунд и не требует чтения документации». Критерий: человек, впервые открывший приложение, собирает приличную сцену без туториала за 3 минуты.

Девиз в README: *«Your music, your stage.»*

## 3. Стек: решение и обоснование

**Flutter (Dart) — один кодхаб для Windows и Android.**

Почему именно он:

- **Material 3 из коробки** и лучшая на сегодня реализация M3 среди кросс-платформенных тулкитов; expressive-часть (shape morph, springy motion) докручивается своим слоем — см. §12.
- **Один язык для ядра, редактора и будущего Android-приложения.** Android-порт — это не «переписать», а «добавить платформенный слой».
- **Fragment shaders** (`flutter_gpu`/GLSL-шейдеры через `FragmentProgram`) работают и на Windows, и на Android — идеально для аудио-реактивных фонов.
- **`CustomPainter` + `canvas`** покрывают редактор сцены (сетки, снапы, ручки, направляющие) без сторонних зависимостей.
- Экспорт видео возможен: рендер кадров в `ui.Image`/RGBA → пайп в **FFmpeg** (bundled `ffmpeg.exe` на Windows, `ffmpeg-kit`-подобный подход на Android).

Что **не** берём и почему:

| Вариант | Почему нет |
|---|---|
| Electron/Tauri + WebGL | Лучший рендер, но 150+ МБ рантайм, M3 Expressive придётся рисовать руками в CSS, Android-переиспользование частичное. |
| C# + WinUI 3 / Avalonia | Отличный Windows, но Android-путь закрыт → переписывание. |
| Kotlin + Compose Multiplatform | Идеальный M3 на Android, но десктопная часть сырее, JVM-рантайм тяжёлый, аудио/видео на JVM неудобны. |
| Rust + собственный UI | Максимальный контроль, нереалистично по срокам для одного человека. |

**Запрещено:** подключать пакеты без Windows-поддержки в `core`/`renderer`; использовать `dart:ffi` в UI-слое; тащить `dart:io` в модели проекта.

Проверка перед добавлением зависимости: Windows ✓, Android (потенциально) ✓, лицензия MIT/BSD/Apache ✓, живой мейнтейнер ✓.

**Форматы файлов:**

| Объект | Расширение | Содержимое |
|---|---|---|
| Проект | `.vsproj` | zip: `project.json` + `assets/` + `analysis.vsan` (кэш анализа) + превью |
| Пак шаблонов | `.vspack` | zip: `pack.json` + `widgets/*` + `scenes/*` + `assets/` |
| Кэш анализа | `analysis.vsan` | бинарный (msgpack) — PCM-фичи по таймлайну, версионированный |
| Пресет виджета | внутри проекта | `JSON` в `layers[]` |

Версионирование во всех файлах: `schemaVersion: 1`, при загрузке — миграции, а не «файл не читается».

## 5. Аудио-ядро

### 5.1 Пайплайн

1. **Декод** → PCM float32 моно+стерео, 48 kHz (движок: FFmpeg на Windows, MediaCodec/FFmpeg на Android — за интерфейсом `AudioDecoder`).
2. **Анализ** (один раз на трек, офлайн, в изоляте):
   - STFT: окно 2048, hop 512, Hann → магнитудный спектр.
   - Полосы: `sub` 20–60, `bass` 60–250, `lowMid` 250–800, `mid` 800–2.5k, `highMid` 2.5k–6k, `high` 6k–12k, `air` 12k–20k (энергия в дБ → нормализация 0..1 по перцентилям трека).
   - Огибающие: RMS, peak, крест-фактор; сглаживание attack/release отдельно.
   - **Бит/темп**: onset detection (spectral flux + пики), автокорреляция → BPM, фаза бита, сетка долей, downbeat.
   - Хрома: 12 бин-классов → тональность (Krumhansl-профили), вероятность смены.
   - Новизна/секции: self-similarity + novelty → границы intro/verse/chorus/bridge (эвристика, помечать как «предположение» в UI).
   - Вейвформа-пики для таймлайна (min/max на 512 сэмплов).
3. **Кэш** `analysis.vsan` — пишется рядом с проектом, переиспользуется.
4. **Realtime**: плеер синхронизируется по `position` и **читает** кэш, а не считает заново. Отсюда — идентичность превью и экспорта.

### 5.2 Шина фич (контракт для виджетов)

Виджеты не лезут в аудио напрямую — они объявляют биндинги к именованным фичам:

| Фича | Тип | Смысл |
|---|---|---|
| `level.rms` / `level.peak` | 0..1 | общая громкость |
| `level.attack` | 0..1 | скорость роста (для «дёрганья») |
| `band.<name>` | 0..1 | энергия полосы |
| `spectrum` | float[64] | лог-сгруппированный спектр для баров |
| `waveform` | float[128] | осциллограмма (снимок окна) |
| `waveform.peaks` | float[512] | пики для скролл-вейвформы |
| `beat.isBeat` | bool | удар в текущем кадре |
| `beat.phase` | 0..1 | фаза внутри доли (0 = удар) |
| `beat.bpm` | float | темп |
| `beat.index` | int | номер удара с начала |
| `energy.short` / `energy.long` | 0..1 | «сейчас громко» vs «в среднем» |
| `chroma` | float[12] | хрома |
| `key` | string | тональность |
| `section` | enum | текущая секция |
| `time.now` / `time.progress` | float | позиция и доля трека |
| `lyric.lineProgress` / `lyric.wordProgress` | 0..1 | прогресс строки/слова |
| `lyric.lineIndex` / `lyric.wordIndex` | int | индексы |

Сглаживание — параметр биндинга (`attack`, `release`, `curve: linear|ease|expo`), а не хардкод в виджете.

**Честное ограничение:** LRCLIB отдаёт построчную синхронизацию. Пословная/послоговая — только если в файле есть enhanced-LRC теги `<mm:ss.xx>`; иначе включаем режим «пропорциональный сплит» с ручной правкой. Не выдавай это за «идеальное пословное распознавание».

## 6. Система шаблонов — главная фича

### 6.1 Три уровня кастомизации

1. **Виджет** — единица на поле (текст, спектр, снег, обложка).
2. **Сцена (scene/layout preset)** — готовый набор слоёв с биндингами. «Применить сцену» → получить готовый вид, потом менять под себя.
3. **Пак (pack)** — набор виджетов + сцен + ассетов + превью, распространяется одним `.vspack`.

### 6.2 Формат виджета

Виджет — папка:

```
widgets/my-thing/
├─ widget.json        # манифест
├─ preview.webp       # превью 512×288
├─ shader.frag        # опционально: GLSL-фрагмент
└─ assets/            # опционально: картинки, шрифты
```

Три способа рендера (`render.type`):

| Тип | Кто может | Что это |
|---|---|---|
| `native` | только встроенные | Dart-рендерер, зарегистрированный по `id`. Полный доступ к canvas. |
| `shader` | сторонние | GLSL-фрагмент + контракт uniforms. Кроссплатформенно, песочница. |
| `composite` | сторонние | Декларативный стек примитивов (текст, фигуры, изображения, частицы, градиенты) с выражениями. Без кода — безопасно и переносимо. |

Сторонние паки **не исполняют** произвольный Dart/JS. Это принципиально: безопасность + гарантия, что шаблон заработает на Android.

### 6.3 Манифест (сокращённый пример)

```json
{
  "schemaVersion": 1,
  "id": "builtin.karaoke",
  "version": "1.0.0",
  "name": { "en": "Karaoke Lyrics", "ru": "Караоке-текст" },
  "author": "VisuSic",
  "license": "MIT",
  "category": "text",
  "tags": ["lyrics", "karaoke", "sync"],
  "requires": { "lyrics": true, "audio": false },
  "anchor": { "default": "bottom-center", "resizable": true, "aspectLock": false },
  "params": [
    { "id": "font", "type": "font", "label": { "en": "Font", "ru": "Шрифт" }, "default": "Inter" },
    { "id": "size", "type": "float", "min": 12, "max": 200, "default": 56, "unit": "px" },
    { "id": "fill", "type": "gradient", "default": ["#FFFFFF", "#FFD84D"] },
    { "id": "mode", "type": "enum", "options": ["wipe", "bounce", "perLetter", "glow"], "default": "wipe" },
    { "id": "nextLines", "type": "int", "min": 0, "max": 3, "default": 1 },
    { "id": "blurInactive", "type": "float", "min": 0, "max": 8, "default": 2 },
    { "id": "pulse", "type": "float", "min": 0, "max": 0.4, "default": 0.08 }
  ],
  "bindings": [
    { "id": "kick", "feature": "beat.isBeat", "release": 180, "curve": "expo" },
    { "id": "bass", "feature": "band.bass", "attack": 20, "release": 220 }
  ],
  "expressions": {
    "scale": "1 + bind.kick * params.pulse"
  },
  "render": { "type": "native", "id": "karaoke" }
}
```

Типы параметров (панель инспектора генерируется из них автоматически): `float`, `int`, `bool`, `enum`, `color`, `gradient`, `font`, `text`, `multiline`, `image`, `video`, `choiceCards`, `vector2`, `range`, `curveEditor`, `date`(не нужен), `group`.

**Выражения** — крошечный безопасный язык (`+ - * / min max clamp lerp sin cos mix`, доступ к `params.*`, `bind.*`, `time.*`, `audio.*`, `lyric.*`). Реализуется парсером на ~300 строк, без `eval` и без внешнего кода. Это то, что даёт «гибкость без плагинов».

### 6.4 Правила хорошего шаблона (в `docs/making-widgets.md`)

- ≤ 12 параметров, из них 3 — «главные» (попадают в быстрый инспектор на канвасе).
- Работает при любом соотношении сторон (тест 16:9, 9:16, 1:1).
- Не требует внешних ассетов, если может обойтись; шрифты — только OFL.
- Не ломается при отсутствии лирики/тишине в треке (graceful empty state).
- Превью обязательно, иначе в библиотеке серая заглушка.

Что должно работать в M1–M2:

**Добавление виджета (критично для «главной фичи»)**
- Библиотека слева: категории, поиск, превью-миниатюры, бейдж «новое».
- **Три способа**: клик по карточке (встаёт в предложенное место), drag-and-drop на канвас (с призраком и снапом), горячая клавиша `W` → палитра с поиском.
- При дропе — **умное размещение**: призрак показывает итоговый прямоугольник, магнит к безопасной зоне, к сетке 8 px, к другим виджетам, подсказка «сверху/снизу от текста» если это спектр.
- Сразу после добавления виджет **выделен**, а в инспекторе открыты 3 главных параметра — не надо искать, где крутить.

**Манипуляции на канвасе**
- Ручки: 8 ресайза + поворот, `Shift` — пропорции, `Alt` — от центра.
- Магнитные направляющие и «красные числа» расстояний (как в Figma).
- Сетка 8/16 px, привязка к безопасной зоне (90% для 16:9, 80% для 9:16).
- Выравнивание/распределение мультивыбора, «прикрепить к краю/центру» (anchor), lock/hide.
- Дублирование `Ctrl+D`, копипаст между проектами, nudge стрелками, `Esc`.
- Контекстное меню: Replace на другой виджет с сохранением биндингов и позиции.

**Слои и таймлайн**
- Список слоёв с drag-сортировкой, группы, цветные теги, mute/solo.
- Виджет имеет `in`/`out` на таймлайне: появляется/исчезает по времени, по удару, по строке лирики.
- Анимации входа/выхода — пресеты (fade, slide, scale, blur-in, mask-wipe), длительность и easing.
- Кейфреймы для любого числового параметра (`Ctrl+K`), кривые bezier.
- Лирическая дорожка: строки как блоки, drag = сдвиг тайминга, колесо = ±10 мс, кнопка «tap to sync» (тапаешь в такт — строки встают).

**Прочее**
- Undo/redo ≥ 100 шагов (командный паттерн, не снапшоты).
- Автосейв каждые 30 с + восстановление после краха.
- Превью-режимы: fill / fit / 100% / полноэкранный «presentation» (без UI) / рамка телефона.
- Горячие клавиши + экран `?` со списком.
- Пустое состояние с «Собрать за 3 минуты» — демо-сцена в один клик.

## 9. Лирика

- **Источник 1: `lrclib.net`** (бесплатный, без ключа, отдаёт `syncedLyrics`/`plainLyrics`). Поиск по `track_name` + `artist_name` + `duration`; берём лучший матч по длительности ±5 с. Кэш на диск.
- **Источник 2:** файл `.lrc` рядом с треком / ручная вставка / перетаскивание.
- **Источник 3 (позже, опционально):** локальный Whisper-форс-алайнер для пословной синхронизации — только как отдельная загрузка, не в основном бинаре.
- Парсер: LRC, enhanced-LRC (word tags), многострочные переводы, метки `[A:]`/`[B:]`.
- Редактор: таблица «время — строка», массовый сдвиг `±`, «tap to sync», кнопка «поделить строку на слова».
- Юридически: текст **не** вшивается в приложение и не перепубликуется — только локальный кэш пользователя. В `docs/` явно: ответственность за права на лирику и музыку — на пользователе.

## 10. Экспорт

| Параметр | Значения |
|---|---|
| Контейнеры | MP4 (H.264 / HEVC), WebM (VP9), MOV (ProRes 422 — опция), GIF (≤10 с) |
| Альфа | WebM VP9 + alpha, MOV ProRes 4444 (для наложения в монтажке) |
| Разрешения | 720p / 1080p / 1440p / 2160p / кастом; привязка к соотношению сцены |
| FPS | 24 / 25 / 30 / 50 / 60 |
| Звук | AAC 320 kbps, нормализация громкости (опция), выбор старта/конца |
| Производительность | libx264 `fast`, опционально NVENC; цель — 1080p60 не медленнее 1× реального времени на средней видеокарте |
| Пакетный экспорт | **Batch**: одна сцена → сразу 16:9 + 9:16 + 1:1 в трёх файлах (главный аргумент для SMM) |
| PNG-секвенция | для тех, кто монтирует в другом редакторе |

Реализация: детерминированный рендер `t = n / fps`, `RepaintBoundary.toImage` → RGBA → stdin FFmpeg (`-f rawvideo -pix_fmt rgba`). Рендер в изоляте/отдельном движке, UI показывает прогресс с ETA и может отменить. Пока идёт экспорт — окно не замирает.

## 12. Дизайн-система: Material 3 Expressive

**Настрой**: тёмная тема по умолчанию, «профессиональный инструмент, но живой». Не неоновая игрушка и не стерильный IDE.

- **Цвет**: схема строится из обложки трека (Material Color Utilities / HCT): `primary/secondary/tertiary`, тональные поверхности, expressive-акценты. 6 встроенных схем + «из обложки» + «своя». Контраст AA обязателен, текст поверх сцены — только с scrim или проверкой контраста.
- **Типографика**: variable-шрифт (Inter или Roboto Flex), 15 размеров M3; в редакторе — компактная шкала (body 13–14, label 11–12), `display` — для заголовков экранов. Для лирики — отдельный набор шрифтов (OFL), выбираемых в инспекторе.
- **Форма**: радиусы 4/8/12/16/28/full; активные состояния «морфят» форму (squircle ⇄ круг) через `ShapeBorder`-анимацию; крупные элементы — expressive-«печенька» (12-точечный squircle).
- **Движение**: пружинная физика (spring), 200–500 мс, `emphasized` easing; press-scale 0.96; появление панелей — slide+fade; смена режима превью — shared-axis. Уважать `MediaQuery.disableAnimations` → минимальная анимация.
- **Компоненты**: split button, FAB-меню, segmented button, chips (фильтры категорий), slider с пузырьком значения, switch, snackbar с undo, bottom sheet (мобильный вид), side sheet (инспектор), tooltip.
- **Плотность**: инспектор — compact (строки 32 px), библиотека — комфортная. Все цели ≥ 32 px.
- **Доступность**: фокус-ринг, tab-навигация по инспектору, `Ctrl+±` масштаб UI, контрастный режим.
- **Локализация**: `en` + `ru` с первого дня (ARB/slang). Строки виджетов — в манифесте (`name: {en, ru}`), отсутствующий перевод → fallback `en`.
- **Иконки**: Material Symbols (Outlined → Filled при активации).

Запрещено: дефолтный `ThemeData()` без кастома, эмодзи вместо иконок, «системные» серые скроллбары поверх тёмной сцены.

## 16. Как работать (правила для агента)

1. **Вертикальные срезы.** Не «сначала весь слой данных, потом весь UI». Делай так, чтобы в конце дня было видно результат на экране.
2. **Один коммит — одна мысль.** Сообщения в стиле Conventional Commits (`feat(editor): snapping guides`).
3. **Не выдумывай API.** Если нужен пакет — проверь версию, платформы, лицензию; зафиксируй в `pubspec.yaml` точную версию.
4. **Документируй решения.** Любой неочевидный выбор → короткий ADR в `docs/adr/`.
5. **Сначала скелет, потом красота.** Но не оставляй «временный» UI дольше одного milestone.
6. **Спрашивай перед:** сменой стека, крупным рефакторингом, добавлением тяжёлой зависимости, изменением формата файла.
7. **Пиши тесты** на всё, что легко сломать: парсер LRC, выражения, миграции проекта, undo, анализ BPM.
8. **Проверяй сборку Windows** после каждого крупного шага, а не в конце.
9. **Готовь Android-путь**: если тянет написать `Platform.isWindows` вне `platform/` — остановись и сделай интерфейс.
10. **Никаких секретов в репозитории**, ключей не требуется вообще (LRCLIB без ключа).

## 17. Анти-цели (сознательно НЕ делаем)

- Не делаем видеоредактор (нет произвольных видео-дорожек, переходов между клипами, многодорожечного монтажа).
- Не делаем социальную сеть, облако, аккаунты, маркетплейс с оплатой.
- Не обещаем «AI сгенерирует клип по описанию» — это другой продукт.
- Не тащим 3D-движок и не делаем «полноценный After Effects».
- Не поддерживаем macOS/Linux в v1 (архитектурно не мешаем, но не тестируем и не обещаем).
- Не храним и не раздаём чужую музыку и тексты.
